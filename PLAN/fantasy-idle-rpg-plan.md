  # 任务：制作一个 2D 网页挂机 RPG 游戏 "fantasy-idle-rpg" （日式中世纪奇幻风）

  ## 项目概述
  请从零开发一个纯前端、可离线运行的 **2D 挂机放置类 RPG 网页游戏**，主题为 **日式中世纪奇幻（JRPG
  风格：剑与魔法、骑士、魔物、公会、地下城）**。游戏以竖版手机端为第一优先适配目标，同时兼容桌面浏览器。最终交付一个可直
  接双击打开或本地静态服务器运行的项目（纯 HTML/CSS/JS 或 Vite 构建均可，优先零依赖或轻依赖）。

  ## 世界观设定（叙事包装）
  - 背景故事（细节可在开发中润色）：沉睡千年的魔王于幻想大陆**「露西亚大陆」**苏醒，瘴气自魔王城向外蔓延，
  逐步侵蚀草原、森林、矿坑与雪山；冒险者公会向全大陆发布讨伐令。玩家是公会新晋的独行冒险者，从前线四个受侵蚀区域之一
  启程，沿八个区域一路净化瘴气、讨伐魔物，最终直捣魔王城。
  - 区域描述、Boss 命名、成就文案、休息/扎营的氛围文本均挂靠这条叙事线，保持语气统一；全部文案走 i18n 语言包。
  - 标题画面采用半俯视悬崖远眺：全景在半分辨率画布逐像素绘制并以 2× 最近邻放大；近景四人围火、游侠在营地同侧的河湾近岸哨戒，完整岩壁明确高台落差；远山曲流在崖口收束并与瀑布同轴，在岩壁下方展成带浅滩、暗岸与河中岩石的横向河湾，营地贴近干燥近岸；巨兽巢穴、不规则混生密林和多重雪山形成清晰景深，魔王城收束为山隘间极远的小比例剪影，以地形层次呈现“从营地走向终局”。
  - 首次进入游戏展示 3~5 句**序章文本**（像素风对话框逐字显示，可点击跳过），之后不再打扰。

  ## 核心玩法需求
  1. **挂机战斗循环（伪实时制）**：战斗采用**伪实时制**（不做严格回合制）——每个实体（角色/怪物）拥有独立的攻击间隔，
  由速度属性决定出手频率，接敌后各自按节奏自动攻击、按冷却放技能；数值平衡以 **1v1 遭遇为基准**，怪物不主动群体围攻，
  AOE 技能可波及周围怪物作为爽点。无需玩家操作即可持续获得经验、金币、装备掉落；
  页面关闭后再打开需结算**离线收益**（按离线时长折算，**不设时长上限**）。
  2. **挂机场景为可位移的平面小世界（必须）**：不采用静态对峙舞台，也不是单纯横/竖卷轴——每个区域是一块伪俯视（3/4
  视角）的 2D 平面场景，角色拥有 x/y 两轴坐标，**自动游走、索敌、走向怪物发起战斗**，怪物在场景中分散刷新；镜头平滑跟随
  角色移动，配合**多层背景视差 + 场景缩放**（如 Boss 登场镜头拉近、战斗时轻微推近）制造纵深与透视变化感。战斗结算逻辑仍
  按第 1 条的自动战斗规则进行，位移与演出不影响挂机数值。
  3. **角色成长**：等级/经验曲线（指数增长）、基础属性（HP/攻击/防御/速度/暴击率/暴击伤害），升级自动成长 +
  可分配属性点二选一实现，任选其一并说明理由。
  4. **装备系统**：武器/护甲/饰品至少 3 个槽位；装备有稀有度（普通/精良/稀有/史诗/传说，用颜色区分：灰/绿/蓝/紫/橙）；支
  持随机词条、装备对比、一键出售低稀有度。
  5. **地图/区域推进**：至少 8 个风格递进的区域，经典内容顺序为：新手草原 → 迷雾森林 → 废弃矿坑 → 亡灵墓地 → 雪山隘口 →
  熔岩洞窟 → 浮空遗迹 → 魔王城。**新档初始化时随机排列前 4 个区域，后 4 个区域保持固定**，使前期路线每档不同；
  怪物强度、Boss 首杀奖励、药水价格、离线收益与推荐等级均按该区域在本档路线中的**推进位置**计算，而非绑定经典区域编号，
  保证随机路线仍按 1～8 阶平滑成长。**Boss 触发采用讨伐进度条**：击杀本区域普通怪积累进度（如 10 只）；讨伐条旁常驻紧凑的
  「讨伐 Boss」按钮与「自动讨伐」开关。自动讨伐默认开启，积满且生命状态安全时 Boss 自动登场；关闭后满进度待命，由按钮手动
  发起且允许玩家自行承担低生命挑战风险。登场配合镜头拉近 + 震屏特效；挑战失败则 Boss 撤场、进度保留，可重新积攒再战。击败 Boss
  解锁下一区域。**「自动推进」开关（默认开启）**：开启时击败 Boss 自动进入下一区域，关闭则原地继续刷本区域；
  支持随时手动回退刷低级区域。**魔王城采用可失守的特殊准入规则**：角色在魔王城内战败并回营时，立即退回本档路线的上一
  区域营地并重新锁定魔王城；玩家须再次击败上一地区 Boss 才能重新解锁。该过程不撤销既有 Boss 首杀、奖励、成就或通关记录，
  重新解锁也不得重复发放首杀奖励。地图面板、自动推进与连续死亡回退必须统一读取本档路线，禁止回退到注册表固定顺序。
  6. **技能系统**：至少 6 个主动/被动技能，自动战斗中按冷却自动释放，可用技能点升级。
  7. **商店与货币**：金币 + 稀有货币**魔晶石**，两者均需**产出/消耗闭环**——魔晶石产出：Boss
  首杀固定奖励、成就奖励、分解传说装备；魔晶石消耗：商店永久增益、稀有装备。商店出售药水、装备、永久增益。
  **药水自动使用规则**：战斗中 HP 低于阈值（默认 30%，设置面板可调）时自动消耗背包中的药水，带短冷却防止连喝；
  无药水时仅靠自然恢复，不中断挂机。
  8. **统计页（必须）与成就（可选加分项）**：基于事件总线的累计**统计计数器**——总击杀、Boss 击杀、总金币/经验、
  装备掉落数、累计游玩与挂机时长等，做成独立统计页（放在角色或设置 Tab 内）展示；**成就**为统计计数器之上的
  累计型达成（击杀 100 只怪等），达成给予金币/魔晶石奖励。
  9. **挂机休息/扎营模式（必须）**：与战斗挂机并列的第二种挂机状态，可在战斗页一键「返回营地」。角色走到场景中的营地点，
  坐在篝火旁进入休息演出（打盹、呼吸起伏、偶尔 Zzz 气泡）；休息期间不战斗、不获得战利品，但 **HP
  快速恢复**，并按休息时长积累「休整」增益（如恢复后一段时间经验/掉率小幅加成，数值温和，防止取代战斗挂机），一键
  「拔营」返回战斗。**离线结算与状态联动**：离线时若处于休息模式，则不产生战斗收益，回归时 HP 满、休整增益按上限积满；
  若处于战斗模式则照常按离线公式结算。此模式定位是**氛围欣赏 + 软性恢复节点**，详见下方「动态氛围与日夜循环」一节。
  营地视觉需形成稳定的前线据点构图：磨损地垫与营火刻印承托帐篷、旗帜、营灯、补给、铺盖、坐木和炊具；休息时首页区域牌与讨伐条切换为营地身份和休整进度，但不得改变世界种子、路线、导航或存档协议。
  10. **死亡/失败逻辑（必须）**：角色 HP 归零**不惩罚**已获得的经验/金币/掉落。死亡时自动脱战，撤退回场景营地点，
  进入短暂「重整」倒计时（5~10 秒，复用扎营坐姿演出）回满 HP 后自动返回战斗，挂机全程不中断。**卡关保护**：同一区域
  连续死亡 3 次时自动回退到上一区域继续挂机，并弹出提示（建议强化装备/升级技能/刷低级区）；Boss 战失败不计入卡关计数，
  仅按第 5 条进度条规则撤场重攒。魔王城例外：普通死亡或最终 Boss 挑战失败均立即执行第 5 条的退回上一地区与重新锁定，
  不等待累计 3 次死亡。

  ### 掉落、采集与探索奖励
  - **地面掉落**：普通战斗的装备/药水以世界实体落地，金币即时入账；Boss、离线及非战斗入口直接入包。`settings.groundLoot` 默认开启，关闭时立即回收；支持接触、点击走近与自动 AI 拾取。单区至多 24 件、单件保留 60 秒；超限、超时、切区、休息、传送、死亡、存档前或页面隐藏时，均经既有入包事务回收，收益不得丢失。
  - **采集与素材**：八区 `gather` 数据各注册两种主题节点与独立 `gather_*` 16-bit 世界精灵，每区确定性生成 3–5 个合法点。16 个节点与 2 个宝箱由透明母版确定性编译为独立 PNG，并按八区/宝箱拆分运行时注册模块；稳定 ID、源图哈希和轻量缺图回退均保留。采集耗时 1.2 秒并会被接敌中断；90–150 秒冷却由世界时钟驱动且支持离线恢复。素材是不占装备容量的计数字典，配方集中在 `formulas`，通过 `camp-exchange` 兑换药水、金币、装备箱和有上限的永久强化。
  - **随机宝箱**：仅合法战斗位移累积发现进度且单帧封顶；传送、回营、休息、过场、死亡和原地站立均不计。同区至多一个宝箱，两次发现至少间隔 60 秒；宝箱 90 秒过期且不持久化。普通木铜箱产出金币/素材，稀有紫晶暗金箱追加装备和小概率魔晶石；两者使用资产注册表精灵，接敌会中断开箱但保留箱体。

  ## 远距回营与手动操控（必须）
  ### 体验目标与规则
  - **远距回营**：点击「返回营地」先清除移动指令与战斗目标。距营地 ≤260 世界像素走完整步行并显示「返回营地」，>260 显示「传送回营」并进入传送状态机（基础移速 56 px/s，阈值≈地面 4.6s / 浅水 6.4s 步行）。
  - **传送四段**：`warpOut（0.38s 收束） -> warpIn（0.42s 落地） -> goCamp（~46px） -> sitting`。落点在营地外侧，最后走近篝火转向坐下；含脚下双环、竖向光柱、星屑、角色淡入淡出与相机跟随，非阻塞 DOM、不改休息收益。
  - **状态安全**：Boss 战可主动「撤离并回营」；点击后先切休息安全态，再同步清除 Boss 实体、目标、路径与登场运镜，按战败规则保留一半讨伐进度。主动撤离不属于战败，在魔王城内也不触发退区或重新锁定。传送期间不索敌/攻击/不受普通怪围攻；可取消未完成传送，已落地则从当前位置恢复。区域初始化、导入休息档、特效关闭、低帧率大 `dt` 均须落到合法状态。
  - **操作表达**：回营按钮使用项目字符网格手绘的帐篷、传送法阵、撤离盾牌、出战剑像素图标，不使用 Emoji；传送中显示「取消传送」，落地步行显示「取消回营」，坐下后显示「拔营出战」。战斗中 HP 低于设置内自动喝药阈值时按钮闪烁；减少动态效果偏好下保留静态红色警示。
  - **自动/手动开关**：舞台常驻双态开关，默认「自动」，原生 `<button role="switch">` + `aria-checked` + ≥44px 触控热区；中英文案不得遮挡区域名、讨伐条、扎营按钮。
  - **自动模式**：自动游走、最近索敌、接敌、按攻速普攻、按冷却放技能、击杀续接；玩家临时点地/点怪，指令完成后恢复 AI。
  - **自动交互与休整**：目标优先级固定为接敌战斗、地面掉落、宝箱、成熟采集节点、游走，新交互不得打断已接敌战斗或旅行。`settings.autoCampRest` 默认关闭；仅在自动操控、无 Boss 且讨伐未满时，于休整增益归零后复用回营链，增益蓄满后复战。手动拔营会取消自动休整并抑制 120 秒。
  - **手动模式**：停自动游走/索敌/续接。点地移动、点怪锁定接敌；桌面支持 `WASD`/方向键连续移动。锁定目标进入攻击范围后普攻与技能仍按伪实时制自动结算（不退化为高频点击器），目标死亡原地待命；Boss 可逼近，未锁定前角色不自动反击。
  - **切换与持久化**：切手动立即解除 AI 目标与路径；切自动清除残留手动指令、下帧恢复 AI。写入 `settings.controlMode`，存档升级 v5；新档与 v1～v4 迁移默认 `auto`，读档/导入/语言切换后开关 UI 同步。聚合事件即时保存，禁每帧写档。

  ## 受约束程序化区域布局（必须）
  ### 状态与兼容
  - v6 引入持久化 `worldSeed:uint32/layoutVersion:1`；新种子优先 Web Crypto、回退 `Math.random`，同时确定性洗牌前四区。v5 以 `strSeed("legacy:" + (createdAt || ts || 0))` 派生种子并保留 `regionOrder`。
  - v7 新档及 v6 迁移档使用 `layoutVersion:2`；迁移只改变一次布局版本，不重置种子/区域顺序。双槽、Base64/JSON 必须保留两字段；v1 生成顺序、数量和导航结果作为兼容协议永久保留。
  - 区域种子由 `worldSeed + region.id + layoutVersion` 派生并拆为 `landmarks/terrain/decor/details/nodes` 独立随机流，禁止细节调整扰动关键点、材质、装饰或采集节点；新增 `nodes` 流不提升布局版本，也不改变既有快照。

  ### 布局与导航
  - `terrain.build()` 生成运行时地标、40–64px 走廊、8px 材质格、16px 导航格、装饰和出生候选；区域注册表只存约束。八区保持 `900×520`、主题/元素池/玩法数值不变；营地 X 10–20%/安全半径 80px，Boss X 70–85%/战斗半径 70px。
  - v2 通过 `patch/decor/detail/waterDecorDensity` 将材质斑块增至 1.9–2.1 倍、细节增至 2.0–2.4 倍、总装饰增至 98–135 个；大型丛聚装饰部分沿路线两侧布置，但不得进入安全区或主走廊。
  - 材质代价：基础 `1.0`、雪/沙 `1.15`、瘴气 `1.3`、水 `1.4`、熔岩 `1.6`；大型装饰仅增加软代价，v2 总代价封顶 `2.8`，所有格可通行。普通怪优先低代价格并保留走廊回退候选；营地/Boss/传送/死亡均读取运行时地标。
  - 本地 EasyStar.js 0.4.4（MIT）统一处理点击、索敌、迎击、游走和近距回营；目标变化/位移 >32px/路径年龄 >0.6s 时重算，失败回退直线。WASD 即时移动但按 `costAt` 降速；状态切换清除旧路径，大 `dt` 限制单步。

  ### UI 与验收
  - 地图面板显示可复制的只读 8 位十六进制种子；正式游戏不可改种，QA 页支持 `?seed=XXXXXXXX&region=id` 并显示实际计数。
  - 自动测试覆盖 v1/v2 八区各 100 种子、固定 v1 快照、确定性/差异、数量/坐标、安全区/走廊、导航/出生/可达性、v5→v10、双槽和导入导出；浏览器覆盖移动/桌面密度与性能、点击/WASD、AI 重寻路、回营、死亡、Boss、切区及大 `dt`。

  ## 探索与程序化开放地图
  - 新档和 v10 迁移档使用 `layoutVersion:3`；八区地图为 `2400×1440` 连续地形。`Game.terrain.generate/validate/repair/mount` 分离纯生成、结构化验证、确定性局部修复和运行时装载，v1/v2 生成与黄金协议继续保留。
  - 每区生成 14–18 个宏观中心、MST 主骨架、3–5 条环路与营地到 Boss 的低重叠替代路线；60–70% 可行走格全部归入主连通分量，必要路线净宽至少 48px。河流、悬崖、密林、塌方、熔岩、虚空和残墙提供真实硬阻挡。
  - 16px 导航格同时保存阻挡、材质、危险、宏观归属和阻挡距离。长途移动采用宏观图与局部 A*、静态缓存、请求队列和 2ms 单帧预算；点触与键盘移动使用扫掠碰撞、分轴滑动及合法点投影，不允许直线穿墙兜底。

  - **最终区域失守锁（v10）**：新增 `world.finalRegionLocked:boolean`；旧档迁移默认 `false`。失守只改变末区准入状态，不得清除 `regionProg.cleared/firstKill`、`meta.completedAt`、奖励或成就；若存档中锁已写入但当前区域仍为末区，读档时回退本档上一地区营地。
  - **开放探索持久化（v11）**：按区域保存迷雾 bitset、地标/资源/奇物/生态图鉴、采集计数、威胁冷却、远征周期和当前远征变化层；v10→v11 保留全部角色养成、经济、路线、Boss 首杀、结局与失守状态，并只将布局升级为 v3。迷雾损坏或尺寸不符时仅重置对应区域探索状态。
  - **区域路线持久化与兼容**：将完整稳定 ID 数组 `world.regionOrder` 写入存档，重载、离线回归、导出/导入后顺序不得变化。
  v1/v2 旧档迁移时写入经典顺序，确保当前区域、解锁关系与难度不突变；读档时去除重复/已下线区域，并将新区域按注册顺序补到末尾。

  ## 标题存档门厅（必须）
  - 每次启动先停留在无遮挡的标题营地观景态，通过明确的「点击进入」打开公会「远征档案」；档案提供 ≥44px 的返回观景入口。已有角色不得直接进入世界；选择档案前冻结主循环、世界时间、离线结算和自动存档，避免预览阶段覆盖原时间戳。
  - 当前只开放稳定槽位 `expedition-1`。槽位描述、标题渲染和进入回调必须按稳定 ID 数组工作；主档与备份档仍是同一逻辑角色槽位的容灾写入，不伪装成多角色档。
  - 纯空档不套用「远征档案」标题、槽位编号、容量或存档信息外壳，改用独立的公会纹章「开始新游戏」主行动；序章/建角未完成的草稿显示「继续登记」，正式档显示职业像素头像、等级、当前区域、游玩时长、路线进度、世界种子、最后保存时间与「继续游戏」。
  - 正式档另提供 ≥44px 的双行「开始新游戏」档案页签，副文案明确提示覆盖当前档案；存档卡右侧提供独立 ≥44px 的「X」删除键。两者都需不可恢复二次确认：新游戏清档后自动衔接空档进入流程，删除只清空主备份并返回空槽。
  - 点击槽位依次执行档案卡收束、营火传送光柱、公会符文扩张、星屑上升和上下像素帘幕；摄像机使用连续缓动，帘幕使用 `steps` 像素节奏，遮罩最深处才开始序章/世界。减少动态效果时移除运动与粒子但保留静态闭幕。
  - 浏览器验收覆盖 390×700/390×844/522×1320、观景态与档案态、空档/草稿/正式档、中英文、44px 触控、无横向溢出、标题冻结、时间戳不被覆盖、覆盖确认、进入中态与进入完成态。

  woff2），加载失败降级为系统字体。

  - 像素素材渲染时必须保持锐利：图片与 Canvas 均设置 `image-rendering: pixelated`，缩放只用整数倍，禁止插值模糊。

  ## 模块化 / 插件化架构（必须，面向未来更新）
  - **核心原则：引擎与内容分离，内容即数据**。引擎代码不写死任何具体区域/怪物/装备/技能，只面向「注册表 + 稳定字符串
  ID」编程。
  - **内容注册表（Registry）**：提供统一注册 API（如 `Game.register('monster', {...})`）；区域、怪物、装备基底、随机词
  条、技能、成就、商店条目全部是注册表条目，按类型分文件存放于 `data/` 目录（如 `data/regions.js`、`data/monsters.js`，
  内容多时可再按区域拆分）。**新增一个区域 = 新增一份数据 + 引入一行脚本**，引擎自动据注册表生成地图列表、刷怪、掉落与
  UI，零引擎改动。
  - **事件总线（EventBus）**：引擎在关键节点广播事件（`monster:killed`、`player:levelup`、`item:dropped`、
  `boss:defeated`、`region:unlocked`、`save:before` 等）；成就、任务、统计等系统一律实现为事件监听器，与战斗核心解耦；
  未来新玩法（转生、活动、新货币）同样以监听器/插件形式接入，不侵入既有系统。
  - **物品事务入口**：`Game.items.use(category,id,opts)` 按注册表统一执行数量、存活/忙碌状态和冷却校验，再处理效果、扣减、冷却及 `item:used` 事件。小/大治疗药水注册为 `heal`，共享 `potion` 组 8 秒冷却；自动喝药、背包药水卡和舞台快捷按钮复用该入口，满血或校验拒绝时不得消耗。
  - **动态交易域**：`Game.trade.registerDynamic(area,{ttl})` 注册不入档的临时交易域，负责到期移除并对上下文事件去重；固定与动态交易域共用同一交易 UI 和访问约束。
  - **交互事件与保存**：掉落、拾取、物品使用、采集、宝箱和自动回营均通过事件总线广播；保存仅响应聚合事件，禁止每帧写档。
  - **目录分层**：`core/`（主循环、时钟、存档、事件总线、注册表）、`systems/`（战斗、移动索敌 AI、掉落、商店、成就……
  每系统一文件，系统间只通过事件与公共状态交互）、`render/`（Canvas 场景、镜头、特效、飘字）、`ui/`（各 Tab
  面板独立模块）、`data/`（纯内容配置，不含逻辑）、`assets/`（素材）。
  - **稳定 ID 与存档兼容**：所有内容引用一律用字符串 ID（如 `"slime_green"`），禁止数组下标；存档只存 ID
  与数值，读档时查注册表还原；遇到已下线的 ID 优雅降级（装备折算金币、区域回退到最近有效区域），绝不崩溃。配合已有的
  版本号字段，迁移采用「版本号 + 迁移函数数组」流水线，逐版本升级旧存档。区域推进顺序同样只保存稳定 ID 数组，
  不保存注册表下标；所有依赖关卡阶位的系统统一通过路线位置查询有效 tier。
  - **数值公式集中**：升级曲线、伤害/命中/暴击公式、掉率、离线收益公式统一放在 `data/formulas.js`，调平衡只改这一处。
  - **资产清单化**：素材经 manifest（资产 ID → 文件路径）间接引用，内容配置里只写资产
  ID；素材缺失时自动落到占位渲染（色块+首字），保证新内容可以「先无图上线」。
  - 加载方式注意：因需支持「双击 file:// 直接可玩」，模块化用**按序加载的普通 `<script>` 标签 + 全局命名空间
  `Game.*`** 实现（ES Modules 在 file:// 协议下会被浏览器 CORS 拦截）；若最终选 Vite 构建路线则直接使用 ES Modules。

  ## 国际化 i18n（必须，首发中英双语）
  - 首发支持 **简体中文（zh-CN，默认语言）+ 英文（en）** 两种语言；架构上按「可随时新增语言包」设计，但本期不做其他语言。
  - **全部用户可见文本走 `t(key)` 翻译函数**，禁止在逻辑/UI 代码中硬编码文案；语言包按语言一文件存放（如
  `i18n/zh-CN.js`、`i18n/en.js`），以嵌套 key 组织（如 `ui.tab.battle`、`monster.slime_green.name`）。
  - **内容文本同样走 key**：注册表条目（怪物/区域/装备/技能/成就）中不直接写名称与描述，只写文本
  key（或按约定由 ID 自动推导 key），译文统一放语言包——新增语言时只需新增一个语言包文件，符合插件化原则。
  - **语言切换**：设置面板内提供切换项，选择持久化到 localStorage，切换后即时刷新界面文案，无需重载页面（UI
  渲染层监听 `locale:changed` 事件重绘即可）。
  - **回退策略**：缺失译文时按 `en → zh-CN → 直接显示 key` 逐级回退，保证漏译不出现空白或报错。
  - **数字格式化随语言走**：大数字缩写在 zh-CN 用「万/亿」，在 en 用「K/M/B/T」，由同一个格式化函数按当前语言分派；
  日期/时长展示同理。
  - 字体注意：所选中文像素字体（方舟像素/Zpix/Fusion Pixel）均覆盖拉丁字符，中英共用一套字体即可；英文文案普遍更长，
  UI 面板与按钮排版需按英文最长文案校验一遍不溢出。

  ## 技术与质量要求
  - 代码结构清晰：严格遵循上一节的模块化/插件化架构，数据配置（怪物表/装备表/区域表/技能表）与逻辑完全分离，便于扩展数值与内容。
  - 游戏主循环用 `requestAnimationFrame` 或固定 tick（如 100ms）驱动，页面不可见时用时间戳补偿而非依赖 setInterval
  精度。
  - **大数字处理**：指数成长曲线后期数值会很大，需在项目早期统一封装数字格式化函数（缩写单位随语言走，见 i18n 一节：
  zh-CN 用 `1.25万` / `3.4亿`，en 用 `12.5K` / `340M`），全局所有伤害/金币/经验显示均走该函数；超出 `Number.MAX_SAFE_INTEGER`
  前用科学计数法或数值上限兜底，避免精度丢失与 UI 溢出。
  - 文本遵循上方 i18n 一节：默认语言为**简体中文**，全部文案经 `t(key)` 与语言包管理；所有文件编码 UTF-8。
  - 数值需自洽：给出一份简短的数值设计说明（升级曲线、DPS 与区域怪物血量的匹配关系、离线收益公式）。
  - **世界交互回归**：`tests/v1_11.test.js` 必须链接旧回归，并覆盖 800 张采集节点布局、掉落概率与保底、物品校验矩阵、合法位移、冷却/离线、兑换域、AI 次序、自动回营、动态交易域及 v8→v9；浏览器覆盖 390×844 中英文、44px 触控、减少动态效果，以及拾取/采集/宝箱/交易/用药/回营全链路。
  - **开放探索回归**：`tests/v1_13.test.js` 覆盖八区 1,600 张完整 v3 布局、5,000 个拓扑模糊种子、黄金摘要、硬阻挡、视线、迷雾、准备度、远征稳定性、离线情报边界和资产来源；`tests/v1_13.balance.test.js` 覆盖五职业各 100 种子与三种 AI 策略。浏览器覆盖 390×700、390×844、522×1320、桌面、中英文、点触/键盘、减少动态效果、关闭环境特效和性能指标。
