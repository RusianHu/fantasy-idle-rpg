# 新怪物注册与中立生态全量重构

## 修订记录与已确认决策

- 2026-07-29 修订：经全链路代码核对，修正挂载语义、区域迁移范围与奖励结算时机，补齐战斗时钟映射、Encounter seed、Variant 快照范围、数值同源与 bundle 合同等规格空白。
- 挂载语义：采用反向挂载声明，EncounterPack 以 `mountTo` 挂进 Population，由编译器确定性聚合；不扩展 patch 的数组语义（现有 patch 对数组为整体替换，保持不变）。
- 实施节奏：保持一步到位，不拆阶段发布；全链路完成后一次统一提升 `BUILD_ID`、一次 bump 存档 v14。建议在独立分支实施，main 与 VPS 保持可部署，不发布中间态。
- 区域迁移：regionProfile 全量迁移，区域、地形约束、探索、交易配置全部纳入编译内容；v1/v2/v3 布局黄金快照逐字节不变是硬门槛。
- 奖励结算：保持逐击杀即时发放；Encounter 授权集合只门控资格，不改变发放时机。

## 评估结论

- 当前 24 只怪物、16 个 Encounter 彼此一致，内容审计及 V2 运行测试全部通过，现有内容没有损坏。
- "新怪物注册入口"并不准确。怪物需要同时存在于旧 [monsters.js](C:/Users/admin/Desktop/HBC%20Web/fantasy-idle-rpg/js/data/monsters.js:10)、新 Pack，以及区域/地图列表；[world.js](C:/Users/admin/Desktop/HBC%20Web/fantasy-idle-rpg/js/systems/world.js:338) 又同时读取两套定义。实测仅注册合法 Actor Pack 可以通过严格审计，但无法进入世界。
- [factory.js](C:/Users/admin/Desktop/HBC%20Web/fantasy-idle-rpg/js/data/packs/regions/factory.js:101) 固定假设"2 普通怪 + 1 Boss"，不支持任意数量、跨区复用、和平变体或 NPC 遭遇。
- patch 机制对数组是整体替换（`compiler.merge`），多个 Pack 修改同一区域生态会互相覆盖，无法支撑"加一只怪只写一个文件"的批量工作流；这是采用反向挂载语义的直接动因。
- 当前 Relation 只能表达 `ally/neutral/hostile`。中立单位不能被世界点击、Action 选中或伤害；不同 Encounter team 又会被强制视为敌对，无法容纳旁观者、护送者或临时中立第三方。
- `variantId` 目前只参与缓存键，不改变 Blueprint；NPC 也不会被正式世界更新、渲染或结算。世界级 relation override 缺少生命周期清理，Actor ID 重置后还有串状态风险。
- 离线结算存在双通道：世界内击杀收益走 rewardProfile，[offline.js](C:/Users/admin/Desktop/HBC%20Web/fantasy-idle-rpg/js/systems/offline.js:28) 仍直接读 `region.monsters + formulas.monsterStats`。两通道常数同源（hp 55/2.05/Boss×11，exp 12/1.95/×18，gold 7/1.9/×14），合并通道时必须以等价断言锁定。
- 结论：内容本身健康，但作者入口、跨注册审计和高级生态能力不合格，按上方已确认决策一次性完成全链路重构。

## 目标架构与接口

- 内容定义只保留一份，正式引用链固定为：`ActorArchetype → ActorVariant → EncounterPack —mountTo→ WorldPopulationProfile → RegionProfile`。这是"定义一次、反向挂载"：新单位 Pack 只写自己的 archetype/variant/encounterPack 与 `mountTo` 声明，不修改任何区域文件。
- 挂载聚合契约：`encounterPack.mountTo[]` 每条声明 `populationId`、正整数 `weight` 与可选条件（白名单仅 tier 区间与显式布尔 flag，禁止内联函数）。Population 本体只声明区域基础生态与槽位规则；编译后的最终 packRefs = 本体条目 + 聚合挂载，顺序固定为 Pack 拓扑序 → encounterPack ID 字典序，与脚本加载顺序无关并计入 fingerprint。挂载目标缺失记 `missing-reference`，同一 encounterPack 对同一 Population 重复挂载记 `duplicate-mount`，非法权重直接拒绝；审计必须输出每区聚合视图与 Actor 到区域的完整反向引用链。
- 新增 `actorVariant`：允许在不更换 ActorInstance ID 的情况下切换 stat/resource/ability/trait/AI/presentation/interaction/engagement profile；`compileBlueprint()` 真正解析 `variantId`，Blueprint 与 Actor 快照显式记录该 ID。Variant 只覆盖白名单字段，必须声明所属 `archetypeId`，继承和转换图禁止循环。
- 新增独立 `encounterPack`：声明任意数量成员、Variant、队形、leash、奖励预算、群体警戒与 `mountTo`；Population 保存本体带权条目与战斗规则引用。
- 新增 `worldPopulationProfile`：声明区域常规生态、稀有单位、守门精英、NPC、Boss 巢穴、出现条件、刷新、离线资格与离线代表单位，并接收 EncounterPack 聚合挂载。职责边界固定为：Population 管 What（谁出现、权重、条件），layout 管 Where（位置、巢穴与 guardian 坐标仍由地形流生成）。
- 新增 `regionProfile`（全量迁移）：现有区域注册表的地形约束、探索、交易、采集与视差/粒子配置连同 Population 引用全部纳入编译内容；区域 Pack 使用与 factory 同型的确定性展开函数，展开输入与现 regions.js 完全一致。迁移后 `Game.reg` 的 region 注册表改为由编译内容自动填充的只读投影（旧消费方 API 不变），手写 `monster` Registry 与 `region.monsters/boss` 双写彻底删除；守门精英 4.2/1.55/1.45 等世界侧硬编码乘数移入精英/Population 定义。
- 新增 `engagementPolicy`，分别定义 `manualAttack`、`autoAggro`、挑衅触发、群体传播、脱战、逃跑、投降、奖励许可、记忆范围与声望后果。
- 新增 `interactionProfile`，使交谈、交易、攻击、任务等动作由能力与配置决定，不再由 `category === 'npc'` 推断。
- Relation 优先级调整为：Actor/Encounter 临时覆盖 → Encounter 显式 team 矩阵 → 世界 Actor/群体记忆 → 声望修正 → Faction 基线 → neutral。不同 team 不再自动敌对，team 也不再直接决定 Encounter 胜负。
- 增加 `Game.engagement.canInitiate()`、`requestAttack()`、`provoke()`、`forgive()`、`snapshot()`；`requestAttack()` 只提交不可变 `EngagementCommand`，不得在 DOM 事件或渲染帧内直接修改 Relation、Actor 或 Encounter。
- 增加 `Game.actors.transitionVariant(actorId, nextVariantId, options)`；默认只允许脱战转换，战中转换必须由已审计的转换边和 cleanup phase 驱动。转换先构建候选 Blueprint/组件快照，通过全部校验后一次提交，失败时 Actor、Encounter 和事件日志均保持不变。
- 普通点击优先交互；中立可攻击单位通过明确的剑图标动作和确认进入战斗。自动模式永不主动攻击中立单位，敌对状态建立后才允许自动接战和 AOE 命中。
- 分层敌对记忆采用数据默认值：实例记忆持续当前 Encounter，普通群体记忆持续 180 世界秒并入档，关键 NPC 记忆持续到赎罪事件，Faction reputation 持久化并可衰减或修复。
- 奖励语义：保持逐击杀即时发放与地面掉落协议不变。Encounter 编译时生成"奖励授权集合"，仅决定资格——observer、objective 与未授权 NPC 击杀不产生 exp/gold/掉落，NPC 不因具有 Vitals 自动掉落；leash、主动撤离、死亡等提前结束天然保留已发放收益。结束结果附带授权统计，只用于审计与测试，不参与发放。
- 数值同源：迁移以 formulas 常数为唯一数值源，区域展开函数继续消费 monsterStats 同源常数；`offline.settle` 与 CombatEstimator 改读编译 Population（`evaluateCurrent` 的首 pack 语义由 Population 首个常规条目继承，离线代表单位由 Population 显式声明）。legacy `ent.atk/def/spd` 世界字段随旧通道删除，审计确认无残余消费方。
- 存档升级至 v14，ActorRecord 增加可选稳定 `variantId`，并新增按稳定 `spawnId/groupId/factionId` 索引的 `world.social`（含需持久化的 `spawnVariants`）；v13 迁移使用 Archetype/Population 默认 Variant 和空社交状态，不持久化临时 Actor ID、Blueprint key、Encounter 或战斗冷却。

### 多阵营 Encounter 与目标契约

- `encounterProfile` 新增 `teamSlots`、方向性 `relationMatrix`、`objectives` 与 `completionPolicy`。team slot 至少声明 `id`、`role: combatant | objective | observer`、可选 `coalitionId`、`countsForCompletion` 和 `rewardEligible`；运行时 Actor 另有 `active | defeated | surrendered | escaped | left` 参与状态。
- `observer` 不建立威胁表且默认不可被 Action 选中，也永不阻止 Encounter 结束；`objective` 可被保护或护送，但是否维持 Encounter 由目标声明决定；援军加入既有 team slot 或显式动态 slot，不靠"team 数量"改变胜负。estimator 的目标枚举与真实战斗同步尊重 role，禁止两者分叉。
- 首批目标 DSL 固定为 `eliminate`、`survive`、`protect`、`surrender`、`escape`、`timeout`，只接受稳定 team/coalition/tag/actor selector 和整数 tick 参数；特殊规则只能引用已注册、版本化且确定性的 objective handler，禁止内容内联函数。
- 每个固定 tick 按 `外部命令 → expire → periodic → movement/resource → resolve/reaction/commit → cleanup → phase/Variant → objective evaluation → AI` 执行。`Game.encounters.evaluateObjectives()` 是唯一自动结束入口，返回 `ongoing | success | failure | draw`；结束结果包含 `winningTeamIds[]`、`winningCoalitionIds[]`、逐目标结果、参与状态和奖励授权集合。旧消费者暂保留只读 `winnerTeamId` 投影：恰有一个获胜 team 时返回其 ID，否则为 `null`，不得再据此实现新逻辑；estimator 场景 `winnerTeamId === 'party'` 的判定继续成立（offline 的 failureRate 依赖它）。
- 现有双阵营 Profile 在编译时补成标准目标："玩家 coalition 至少一名 combatant 存活且所有敌对 combatant 均 defeated/surrendered/escaped"；该兼容投影必须保持现有 16 个 Encounter 的战斗时长、Boss phase 与首杀结果不变。
- 终止判定移位说明：objective evaluation 位于 AI 之前，而现行 `checkEnd` 在 AI 之后。因 AI 当 tick 提交的动作最早在下一 tick 的 resolve phase 生效，结束 tick 不得改变；唯一预期差异是最终 tick 不再产生 AI 派生事件。新旧差分夹具只比较结束 tick、胜负、Boss phase 与奖励授权，并显式豁免最终 tick 的 AI 事件。

### Engagement 固定 tick 事务

- `Game.combat` 维护独立于渲染帧的 50ms 整数 `combatClockTick`；即使当前没有 Encounter，只要存在外部战斗命令也继续推进。UI、世界点击和脚本只能向队列写入 `{commandId, requestedTick, sourceStableKey, targetStableKey, kind, openingAbilityId?}`，队列按 `requestedTick → sourceStableKey → targetStableKey → commandId` 稳定排序。
- 时钟映射：`combatClockTick` 只用于命令排序与提交时点，Encounter 内部 tick 保持 0 起算，事件日志与黄金快照协议不变；两钟以"命令在其 requestedTick 之后的第一个 Encounter tick 前处理"衔接。长时间无战斗后收到首条命令时，命令钟直接跳齐当前时间、不做追帧补算；Encounter 追帧仍受 `maxCatchupTicks` 约束。
- `Game.engagement.processCommands(tick)` 在该 tick 的所有 Encounter phase 之前运行。重复 `commandId` 幂等返回原结果；切区、回营、读档、Actor despawn 或目标 spawn generation 改变时，未提交命令以结构化原因取消，命令队列不入档。
- prepare 阶段无副作用地校验双方实例与稳定世界键、EngagementPolicy、保护状态、当前 Encounter 占用、leash/区域、目标 Variant、群体传播范围、team slot、EncounterProfile、Relation 变更和可选 opening Action。中立非战斗 NPC 的 `onProvokedVariantId` 必须在此时先编译并验证其战斗能力。
- commit 阶段通过 `Game.encounters.startAtomic(plan)` 一次完成必要 Variant 转换、带 owner/scope 的 Relation 记录、Encounter 创建、全体 join、team matrix、群体警戒和 priority target；任何内部失败按 prepare 快照逆序恢复，不发出局部事件、不消耗 RNG、不留下半加入 Actor。Encounter seed 只由世界 seed、区域、稳定 spawn/group key、Population encounter ordinal 和 Profile ID 派生，不使用临时 Actor ID、时间戳或对象遍历顺序。ordinal 为 per-spawnKey 运行时计数、不入档；读档后从 1 重置属有意行为（相同世界状态重放相同战斗序列），不同 spawnKey 计数互不影响。
- commit 成功后在同一 combat tick 尝试提交 opening Action。非法 ability 在 prepare 阶段拒绝整个命令；合法 Action 因距离、GCD、资源或 busy 暂不能开始时，不回滚已经成立的挑衅与 Encounter，而是保留 priority target，由正式移动/队列/AI 管线继续，禁止绕过射程、冷却或行动锁。
- 事务只在最终 commit 后按固定顺序发布 `actor:variantChanged? → relation:changed → encounter:started/joined → engagement:committed → action:started?`；失败仅发布一个 `engagement:rejected`。监听器不得在事务中途观察或改写半成品状态。

### Variant 转换事务

- `actorVariant` 可声明 `transitions`，每条边固定 `from/to`、允许的 `triggerId`、`timing: outOfEncounter | cleanup`、`activeAction: defer | cancel` 与 `persistence: none | actorRecord | worldSpawn`。未声明转换边、跨 archetype、战斗中移除 Vitals/Action 能力或改变 ActorRecord 身份的请求一律拒绝。
- 脱战转换立即进入 prepare/commit；战中转换只排入当前 Encounter cleanup phase。`defer` 等到 ActionState idle，`cancel` 必须复用正式 `cancelAction()` 退款，并按 action token 清除 scheduler、telegraph、预留资源和 queued Action，禁止把旧 ability 的延迟事件带入新 Blueprint。
- 固定迁移矩阵为：instance/record/spawn/transform/party/team/faction/controller/encounter 身份保持；HP 按旧最大生命比例映射并 clamp；同 ID Resource、Ability cooldown/group/charge 保留剩余 tick 并按新上限 clamp，新项取初始值、删除项丢弃；兼容 Status/Shield/Threat/Targeting 保留，带 `removeOnVariantChange` 或引用已失效组件的状态在 cleanup 中以确定顺序移除；Combo 仅在新 Blueprint 仍授予对应链时保留；AI、Presentation、Body、Interaction 与 Engagement 读取新 Blueprint。
- prepare 使用受影响 Actor 与相关 Encounter 的快照构造候选组件，重新应用 Trait、Status 和外部 Modifier ledger，并验证数值有限、组件前置条件、team/objective 能力、scheduler 引用和资源边界；快照限定为回滚所需最小集（受影响 Actor 组件、Encounter 的 team/threat/scheduler 引用与事件 sequence 水位），禁止克隆 eventLog 全量。commit 只允许一次引用替换；异常时恢复原快照且不得增加事件 sequence，成功后才发出一条包含 old/new Variant 和迁移摘要的 `actor:variantChanged`。
- `transitionVariant()` 本身不决定长期状态。Roster Actor 的持久 Variant 写入 ActorRecord；稳定世界 NPC 仅在转换边声明 `worldSpawn` 时写入 `world.social.spawnVariants[spawnId]`；普通怪、召唤物和 `persistence:none` 重生后回到 Population 声明的默认 Variant。存档永不保存 ActorInstance ID、Blueprint key、施法或冷却。

## 测试与验收

- 作者 fixture 只增加一个含 `mountTo` 的 Pack，即可编译、生成并运行普通怪、中立非战斗 NPC、中立可攻击生物、战斗 NPC Variant 和召唤物；不得修改 world/combat/renderer 及任何区域文件。
- 挂载聚合确定性：同一 Pack 集合在不同注册顺序下 fingerprint 与聚合 packRefs 完全一致；duplicate-mount、缺失 Population、非法权重、非法条件必须被严格审计拒绝。
- 缺失 Population、EncounterPack、Variant、i18n、资产或嵌套 profile 引用必须被严格审计拒绝；显式 `labOnly/summonOnly/future` 才允许未进入世界。
